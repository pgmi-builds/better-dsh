# Chapter 22: i18n & Translation

## Core Idea
Every in-scope dsh document is maintained as an equal-authority English/Simplified-Chinese pair of three sibling files (`foo.md`, `foo.zh.md`, `foo.i18n.yaml`), mechanically gated by blob-hash consistency records plus structural-signature checks, with terminology.md as the single source of truth for term rendering.

## Frameworks Introduced
- **Pairing contract**: both languages carry equal authority; a PR never lands one side without the other two files.
  - When to use: any edit to an in-scope document.
  - How: update the counterpart directly in one terminology-guided pass, then `pnpm run verify-translation-pairing --write <pair>` re-records both blob hashes; that yaml diff is the reviewable confirmation act.
- **Consistency record (`foo.i18n.yaml`)**: full git blob hash (`git hash-object`) of each side at last confirmation — content comparison, computable within one PR; recovers exact last-confirmed text for minimal patch-style resync (never re-translate whole files).
- **Structural signature**: heading depths/order, fenced code blocks (byte-identical incl. comments), table row/column counts, list kinds/starts/item counts, semantic link targets with exact query/fragment suffixes — must match 1:1 across the pair.
- **Translation rules (RFC 2119 levels)**: MUST/MUST NOT gate-blocking, SHOULD needs stated deviation reason, MAY discretionary; register calibrated by style-samples gold pairs (sample wins over prose voice rules on conflict).
- **Translation prompt pipeline**: `scripts/translation-prompt.ts` renders the committed template with only `{{source_lang}}`, `{{target_lang}}`, `{{terminology}}` placeholders; output is three XML sections (`<translation>` / `<review>` / `<final>`), pipeline takes `<final>`; 5 human-reviewed whole-document gold pairs injected as few-shot example conversations.

## Key Concepts
- **Language switcher**: Chinese file links back right after H1: `[English](foo.md) | 中文`; authored English files reciprocate; generated English sources omit it (stay byte-identical to generator output).
- **Exclusions** (never paired): `cordis-api/inherited.md`, AGENTS.md/CLAUDE.md instruction files, `terminology.md` + `style-samples.md` (bilingual by construction), `translation-prompt.md` (machine-consumed verbatim), `.agents/notes/archived/` (frozen, sealed).
- **Term classes**: 缩写类 (ACP, LLM, SSE — abbreviations in both languages); 英文类 (agent, seam, slot, fiber — keep English in Chinese prose); 双语类 (adapter→适配器, session→会话 — translate, with 不要译作 prohibitions).
- **First-occurrence annotation**: write the 首次出现 value on first prose occurrence (e.g. `agent（智能体）`), bare form afterward; a term already glossed inside a compound needs no re-gloss.
- **Pending terms**: unlisted terms without established major-OSS precedent (K8s/Vue/MDN/微软) stay English and go under 待定术语; no inline invention.
- **Protected tokens**: inline code spans — commands, flags, paths, identifiers, API/event names, config keys, versions — verbatim, never translated; fenced code blocks byte-identical including comments.
- **Chinese typography**: half-width space between Chinese and Latin/numerals; full-width punctuation `，。：；？！（）「」`; 顿号 for parallel lists; no full-width digits; 你 not 您; RFC 2119 → 必须/禁止/应当/可以 preserving emphasis strength.
- **Merge driver**: `dsh-translation-pairing` composes records when both owner blobs merge cleanly; fails closed otherwise; `pnpm run resolve-translation-pairing-conflicts` for stopped merges.

## Mental Models
- Think of the gate as proof of confirmation, not soundness: green = hashes and structure match; whether the two sides truly say the same thing is the reviewer's half.
- Use the lightweight path (translate directly, one pass, load terminology first) for routine agent work; the `dsh-translate-docs` skill workflow only on explicit user invocation.
- Treat out-of-sync resync as patching: diff the edited side against its last-confirmed hash, apply the minimal counterpart patch — never re-translate the file.
- Think of authority order in the prompt: source meaning/structure > terminology table > gold pairs > prompt guidance; gold pairs calibrate voice, they are not a translation memory.

## Anti-patterns
- **Editing one side of a pair without the other**: CI goes red; a scoped green (`verify-translation-pairing <pair>`) never substitutes for the corpus-wide run at PR level.
- **Translating code identifiers or fence contents**: byte-identical requirement; ` ```ts ` fences also compile under doc-typecheck.
- **Using a 不要译作 rendering** (e.g. 接缝 for seam, 智能体笔记 for Agent Note, 金丝雀测试 for canary): strictly forbidden.
- **Conflating term pairs**: capability→能力 vs feature→功能; inference vs reasoning (gloss only when disambiguation needed); stale→陈旧 vs expired→过期.
- **Copying the language switcher unchanged when translating**: flip it; if the source has none, don't invent a filename — the pipeline inserts the canonical switcher post-parse.

## Key Takeaways
1. A PR editing either side updates the counterpart and re-records the pair in the same change — the yaml hash diff is the reviewable act of confirming consistency.
2. Load terminology.md before translating; every listed term follows its row, its 首次出现 annotation, and its 不要译作 prohibitions, in both directions.
3. Structure mirrors one-to-one: headings, list shape, table dimensions, code fences, and link targets (with locale-swapped `.md`/`.zh.md` paths inside the corpus) must match.
4. The prompt pipeline recognizes only three placeholders and whole-document translation; output framing escapes lines that look like wrapper tags with one extra backslash.
5. Routine work never delegates translation to a subagent or runs a separate review pass — one direct terminology-guided pass, then the gate.
6. Chinese register = institutional technical Chinese with explicit actors (系统/门禁/评审人) replacing vague passives; established engineering idiom (误报/漏检) over calques.
