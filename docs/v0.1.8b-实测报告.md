## 1. 决策一：移除 `refine`（本轮，2026-08-24）

`refine` 是抄 Prime Agent 的 **Continual Harness**（Prime Agent 三大支柱：RLM / Context as variable / Continual harness）。移除理由（用户定）：

**1.1 定位与界限不清**
- `refine` 功能上接近「记忆 / 技能」（memory / skill）。
- Hermes、openclaw 这类 Persona Agent 已经在做 cross-session enhancement（harness 跨 session persist）。
- DASHR 在 runtime 内重组 System Prompt 确实难得；但**同 session 重组后 persist 下来，下个 session 也会带着这个 harness**——这混淆了 **cross-session（跨会话）** 与 **per-session real-time（会话内实时）** 的界限。
- 很多「当时当地有用」的配置并不该跨 session 固化；做 coding/项目的 agent，用户更倾向**每次唤醒时外围 harness 固定、可控**，需要调整再走别的机制。
- 核心未决问题：**Dash 的定位到底是 Persona Agent（人格体、跨会话增强），还是 CLI 式（每次唤醒执行独立新任务）？** 定位不清，refine 的语义就悬空。

**1.2 有效性待测**
- real-time harness 的作用有多大未验证。
- 它是在 runtime 内由**旁路大模型**做总结，且 persist over session——多一次推理、多一层持久状态，收益不明确。
- Memory / Skill 已经有外围插件填补了生态位；唯一缺口只是「不能在 runtime 内实时重组」，而「实时重组」目前看偏超前、有效性存疑。

**1.3 模型没空主动调它（用户补充）**
- 大模型几乎**每一个 turn、每一个 user prompt 都有任务要做**，不会「有心思」在 runtime 里主动去调用 refine 这种自我维护动作。
- 让模型在忙正事的同时抽空做 harness 重组，是天方夜谭；它只会专注手头任务。

**可逆性**：项目有 Git 版本控制，随时可切回 v0.1.6 或更早查看源码；上游 Prime Agent 也在做相关探索，届时可再引入。故本次**暂不引入 Refine**。

## 2. 决策二：移除 `compact`（上轮已定）

`compact` 是把宿主 `ctx.compaction` 引擎硬桥进 REPL 的 DASHR 独有桥接。移除理由：
- 上下文压缩是**宿主运行时的事**，不属于 REPL（REPL 是 Agent 运行时的「外部环境」）。
- 原生工具链根本没有 `compact` 工具（只有 CLI 命令 + 压缩引擎 service），DASHR 是「无中生有」映射进来的。
- 实测 `tool.compact` 一调就返回 `no ctx.compaction engine is mounted`（本部署未挂引擎），映射了也没意义。
- 程序逻辑上「既不桥接、也不屏蔽」最简洁——上游不提供，删掉即自然缺位。

> 注意：移除的是 `tool.compact` 这个**模型可见的 REPL 桥接**；被动 recency 压缩引擎（`RecencyAwareCompactionEngine`，`auto: true` 后台自动压）**保留**——两者是两回事（见 §4）。

## 4. 落地范围（已定稿：refine 删、recency 保留）

**移除 —— refine（Continual Harness）：**
1. `BRIDGE_TOOL_SCHEMAS` 删 `refine` 条目（留 `send_message`）。
2. 删 `refineCallable` 函数 + bindings 装配处 `refine: refineCallable`。
3. 删 `src/refine.ts`、`src/harness-store.ts`（及其测试）。
4. 删 `refineModel` 配置项 + `resolveRefineTarget` + `requireLlm` 相关 wiring。
5. 删 `dashr:harness` prompt 段（refine 是唯一写入方，删后必然为空）。

**移除 —— compact（仅 `tool.compact` 桥接，不动 recency）：**
6. `BRIDGE_TOOL_SCHEMAS` 删 `compact` 条目。
7. 删 `compactCallable` 函数 + bindings 装配处 `compact: compactCallable`。

**保留：**
- `send_message` 桥接（A2A 双向）。
- `eval`（传输核心）。
- **被动 recency 压缩引擎**：`src/compaction/recency-engine.ts`（`RecencyAwareCompactionEngine`，`auto: true` step 间自动压）+ `compactModel` 配置 + `src/compaction-surface.ts` + `scopedCompaction` wiring —— **全部保留**（被动压缩有用，且不占 REPL 面）。
