### 「非平坦」的精确口径（纠正常见误读）

`isFlatBindableName`（`src/py-sdk.ts:447`）四条件**同时**满足才叫「平坦（flat-bindable）」：

1. 匹配 `^[A-Za-z_][A-Za-z0-9_]*$`（纯 ASCII 标识符）；
2. 不以 `_` 开头；
3. 非保留字（ECMAScript ∪ Python 并集）；
4. 非 5 个保留绑定全局（`console`/`__dsh_main__`/`__builtins__`/`__name__`/`__debug__`）。

**`__` 中缀本身不构成非平坦**——`__` 是合法 Python 标识符字符。实测：

- `'mcp__server__tool'.isidentifier()` = `True`（纯 `__` 中缀、无连字符 → 合法，可平坦绑定）；
- 真实 MCP 名 `mcp__orch-a2a__a2a_agents` 的 `isidentifier()` = `False`。

**真正的元凶是连字符 `-`**（server 段 `orch-a2a`/`web-reader`/`zai-vision`），不是 `__`。所以「包含 `__` 就叫非平坦」是常见但不精确的 shorthand：`__` 是 MCP 命名约定的**作用域分隔符**，而让它非法的是名字里混进的 `-`（及任何非 `[A-Za-z0-9_]` 字符）。

## §5 eval 工具描述与行为不一致（❌ discrepancy）

- **现象**：`eval` 的 model-facing 描述承诺「top-level `await` and `return` work」——`EVAL_DESCRIPTION`/`EVAL_CELL_PARAM_DESCRIPTION`（`src/index.ts:205-217`），control 段 `control-prompt.md:8` 同文。运行期顶层 `return` 是 SyntaxError。
- **复现（本会话第一人称）**：cell `x = 41; print(...); return "cell finished"` → `SyntaxError: 'return' outside function`（`_DashrTopLevelReturnChecker` 于 AST 访问期抛出，`src/bootstrap.ts:231-250`）；去掉 return 即正常。行为有测试固化：`test/runtime.spec.ts:92`「rejects a top-level 'return' as a SyntaxError, like a native IPython cell」。
- **机制**：kernel 按纯 IPython REPL 语义运行 cell——module scope（globals=locals）、`PyCF_ALLOW_TOP_LEVEL_AWAIT` 编译 + `eval`/`await` 执行模块协程（`src/bootstrap.ts:255-280`）；顶层 `return`/`yield` 由 checker 显式判 SyntaxError，嵌套函数/类/λ 内 return 语义保留（与原生 Python 一致）。
- **根因**：描述文本是旧设计残留——blueprint（`docs/plans/dashr-blueprint.md:499`「top-level return = rewriter 改写为 `_DashrReturn`（BaseException）」）在 08-19 原生语义重构后**未随实现同步更新**；实现侧注释（`src/python.ts:6`、`src/bootstrap.ts:257-260`）写的是正确语义。**contract 对模型撒谎：承诺了 kernel 刻意拒绝的特性。**
- **影响**：模型按描述在 cell 内写顶层 `return`（本会话即发生），白费一轮往返。
- **await 条款核实（非 discrepancy）**：描述中「top-level `await` works」行为为真——kernel 确以 `PyCF_ALLOW_TOP_LEVEL_AWAIT` 编译并运行模块协程；且该能力是环境特性而非纯 Python（实测见会话讨论），故保留该条款必要且准确，仅 `return` 条款需修正。

**总体判定：REPL 正确挂载；工具面存在 1 处回归（`subagent` 泄漏）+ 1 处描述不一致（eval 顶层 `return` 承诺与行为相悖，await 条款属实）；MCP 桥接 best-effort 有文档说明、属事实局限而非缺陷。**

## D1 后续处理（2026-09-01，v0.2.1b）

**根因已确认（源码核实 + 会话日志实证）**：standard preset（`dsh-agent-presets/presets/standard/agent.cordis.yml`）的 `tool-subagent` 行配置 `modelSelectionSettings: true` → dsh-tool-subagent 的 `agent/created` 监听走 `candidate.ctx.inject([...])`，把 subagent 工具注册到**该 agent 自己的层**（own layer）；registry `restrict` 只过滤 inherited 名（global + ancestors），own-layer 名永远可见、不可 restrict（dsh-tools `view()` 对 own.tools 无条件 visible）→ `restrict({deny:['subagent']})` 抛「unknown global tool」→ DASHR mask catch 静默跳过 → 全表面泄漏。其余八名（subagent_fork / workflow / ralph 等）无 modelSelectionSettings → composition 层 → 可 restrict → 正常。**v0.2.1 报告的 fallbacks 假设不成立**（06e516a 全为 LLM failover 机制）。

**v0.2.1b 决策（用户拍板，临时方案）**：接受暴露，不做 mask/覆盖——`subagent` 从 `MASKED_TOOL_NAMES` 移除（九名 → 八名）；在 `control-prompt.md` 自由文本注解 `subagent` 为 `agent`（统一 agent-spawn 入口）的 alias、两者经同一 runtime 委托，保持模型面逻辑自洽。彻底方案（部署配置 modelSelectionSettings: false / DASHR own-layer 防线 / 上游修复）另行 change。
