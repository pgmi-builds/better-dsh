### 「非平坦」的精确口径（纠正常见误读）

`isFlatBindableName`（`src/py-sdk.ts:447`）四条件**同时**满足才叫「平坦（flat-bindable）」：

1. 匹配 `^[A-Za-z_][A-Za-z0-9_]*$`（纯 ASCII 标识符）；
2. 不以 `_` 开头；
3. 非保留字（ECMAScript ∪ Python 并集）；
4. 非 5 个保留绑定全局（`console`/`__dsh_main__`/`__builtins__`/`__name__`/`__debug__`）。

**`__` 中缀本身不构成非平坦**——`__` 是合法 Python 标识符字符。实测：

- `'mcp__server__tool'.isidentifier()` = `True`（纯 `__` 中缀、无连字符 → 合法，可平坦绑定）；
- 真实 MCP 名 `mcp__orch-a2a__a2a_agents` 的 `isidentifier()` = `False`。

**真正的元凶是连字符 `-`**（server 段 `orch-a2a`/`web-reader`/`zai-vision`），不是 `__`。所以「包含 `__` 就叫非平坦」是常见但不精确的 shorthand：`__` 是 MCP 命名约定的**作用域分隔符**，而让它非法的是名字里混进的 `-`（及任何非 `[A-Za-z0-9_]` 字符）。

## §4 prompt hint 到位情况（✅ 已说明，属事实局限，非 defect）

用户的判定标尺：hint 缺失 → defect/discrepancy；hint 已在而运行期确实做不到 → 事实局限。**结论落在后者**。

- [x] **hint 在位**。system prompt 的「Calling tools from the scripting pad」段（=`dashr:tool-catalog` 节的 `REPL_BRIDGE_INSTRUCTIONS`，`src/py-sdk.ts:616`）逐字给出：
  > Tool names that are not plain identifiers (for example MCP names with hyphens or `__` infixes) have no `tool.<name>` member — call those as direct tool calls.
- [x] 运行期确实如此（§3 已证：14 MCP 工具 0 绑定，仅直接调用可达）。**文档与实现一致，是已声明的边界，不是缺说明的 defect。**
- [~] 次要观察 O2：hint 只在 **catalog 段**（`dashr:tool-catalog`）给出；**control 段**（`dashr/control-prompt.md`，「Tools inside a cell」写的是「every native tool is a member of the `tool` object」）**未提**非平坦例外。二者同在 system prompt、且 control 段的「native tool」措辞与 MCP 工具不在同一范畴，故不算自相矛盾；但若未来 control 段独立渲染（脱离 catalog 段），hint 会随 catalog 段一起消失——记录为提示性观察。
