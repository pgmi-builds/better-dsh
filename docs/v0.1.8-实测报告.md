# DASHR v0.1.8 实测报告

> 实测方式：以 DASHR agent 运行时自身（本会话，运行于 dsh Web GUI）作为被测对象，直接调用 `eval` 持久内核与 `tool.*` 绑定逐一实测，并运行仓库 `npm test` 测试套件交叉验证。
> 实测日期：2026-08-24

---

## 0. 摘要（TL;DR）

| 结论 | 结果 |
|---|---|
| 核心 REPL 能力（`eval` 持久内核、`tool.*` 绑定、masking、`rlm` 递归、A2A） | ✅ **全部实测可用** |
| 测试套件 | ⚠️ **155/163 通过，8 个失败** |
| 失败根因 | 🔴 **snapshot 快照/恢复功能失效**（`dill` 缺失 + 内核运行在 Python 3.14.4 而非文档要求的 3.11） |
| 文档/命名漂移 | 🟡 若干（`agent_message` vs `send_message`、flat-global vs `tool.*`、`fgm` vs `pgmi` 等） |

**一句话结论**：v0.1.8 的「eval 持久内核 + 统一 `tool.*` 桥接」这条主线功能是**成立且可用的**，递归子代理（RLM）与 A2A 通信全链路走通；但 **snapshot 快照/恢复（README 标注的 `dill` 全命名空间快照）在当前环境是坏的**，且存在多处文档与代码的命名/架构漂移。

## 2. v0.1.8 相对 v0.1.6 的关键变化（读代码 + 文档得出）

1. **Rebrand**：`dsh-rlm-mode` → `@fgm-builds/dashr`，定位从「RLM 插件」转向「Better Dash 完整 App（distro）」（`docs/repositioning-and-rebranding.md`、`docs/distro-blueprint.md`）。
2. **架构升级（最大改动）**：`cordis.patch.yml` 从 `[]`（空壳）改为在 **HOST 平面** 挂载 `dashr-repl`（`eval` 工具 + 持久 kernel REPL 运行时落到全局作用域层，对所有 preset 可见）。旧的 `preset/rlm-mode/agent.cordis.yml`、`preset.yml` **删除**——这是 v0.1.5「DashrDaemon 空壳」的正式落地。
3. **传输工具改名**：`run_cell` → **`eval`**（`EVAL_NAME = 'eval'`）。
4. **绑定形态切换**：从 v0.1.5 的「平级 top-level global」切到 **统一 `tool.*` namespace**（每工具 = `await tool.name({...})` 成员 async callable），对应 distro-blueprint §2.2 的「dual exposure / both 模式」。
5. **Masking 名单扩充**：`MASKED_TOOL_NAMES` 含 **8 个名**（ADR-0002 只写 7 个，实际多了 `report`）：`subagent, subagent_fork, send_message, list_agents, interrupt_agent, workflow, ralph, report`。
6. **桥接工具**（bridge tools，`BRIDGE_TOOL_SCHEMAS`）：`rlm` / `send_message` / `agent_list` / `rlm_workflow` / `rlm_ralph`。

## 3. 实测结果 — 功能面（逐项亲测）

### ✅ 3.1 `eval` 持久内核 —— 通过

`eval` cell 正常执行，内核为真实 IPython 持久内核，`await` / 顶层表达式 / 变量跨 cell 存续均正常。

### ✅ 3.2 状态跨 cell 持久化 —— 通过

Cell 1 定义 `persist_probe`，Cell 4 仍可读：`persist_probe still alive: {'made_in': 'cell-1', 'answer': 42}`。

### ✅ 3.3 `tool.*` 统一绑定 —— 通过

`tool.read` / `tool.bash` / `tool.grep` / `tool.glob` / `tool.write` / `tool.edit` / `tool.web_search` / `tool.skill` / `tool.memory_*` / `tool.refine` / `tool.todo_write` / `tool.get_goal` 均可用（实测调用返回正确 JSON）。

### ✅ 3.4 `ToolCallError` 类型化拒绝 —— 通过

真实工具调用失败（文件不存在）抛 `ToolCallError`，`.toolName` 正确携带绑定名：

```
caught ToolCallError: ToolCallError | toolName = read
```

### ✅ 3.5 `asyncio.gather` fan-out —— 通过

并发 `tool.read` + `tool.bash` 同 cell 完成。

### ✅ 3.6 Masking（呈现层排除，host 端拒绝）—— 通过（REPL 内）

`tool.subagent` / `tool.list_agents` / `tool.interrupt_agent` / `tool.workflow` / `tool.ralph` / `tool.subagent_fork` / `tool.send_message`(上游工具名) → 全部返回 `ToolCallError: unknown binding`。
legacy 传输名 `tool.run_cell` / `tool.run_code` / `tool.ipython` / `tool.eval`（嵌套）→ 同样 `unknown binding`（`eval` 自身不可重入）。

> 关键机制：`_DashrBindingHolder.__getattr__` 对**任意**名字都返回 proxy（`getattr` 永不抛 AttributeError），真实「是否绑定」由 host 在**调用时**判定拒绝。因此 `dir(tool)` 为 0 成员、`getattr` 恒真——需要**调用**才能区分 masked 与否。

### ✅ 3.7 桥接工具 —— 通过

| 桥接名 | 实测 |
|---|---|
| `tool.rlm` | `rlm({"mode":"bogus"})` → 结构化错误值 `{'error': 'rlm() requires ...'}`（非异常） |
| `tool.agent_list` | 返回子代理列表 |
| `tool.send_message` | 上行/下行均走通（见 3.9/3.10） |
| `tool.rlm_workflow` | 校验失败抛 `ToolCallError`（missing meta.name） |
| `tool.rlm_ralph` | 实际触发一次 Ralph 循环（`status: blocked`） |

### ✅ 3.8 RLM 递归子代理全链路 —— 通过

```
rlm spawn → {'kind':'continuable','subagentId':'26e2842e-...'}
child 完成上报: "42"（6*7）
send_message 下行追问 7*8 → child 再上报: "56"
```

spawn → child 执行 → wakeup 上报 → parent 下行追问 → 再上报，**完整闭环走通**。

### ✅ 3.9 `agent_list` 状态流转 —— 通过

`running → ready`（`ready` = 空闲可续聊，非终结态）。

### ✅ 3.10 A2A 上行 guard —— 通过

root 调 `tool.send_message(receiver='parent')` → 结构化错误：`only a live continuable child agent can report to its parent`（`authorizeReporter` 的 `UNAUTHORIZED` 路径，root 不具上行资格）。

### ✅ 3.11 REPL 语义 —— 通过

顶层 `return` → `SyntaxError: 'return' outside function`（parse 期即拒绝，符合原生 IPython cell 语义）。

### ⚠️ 3.12 `compact` 压缩 —— 本环境不可用

`tool.compact` 返回 `{'context_tokens': 88407, 'error': 'compact() is unavailable: no ctx.compaction engine is ...'}`——宿主 `ctx.compaction` 引擎未在本部署加载，压缩能力无实际效果。

### 🔴 3.13 snapshot 快照/恢复 —— 失效

见 §5/§6，根因是 `dill` 缺失。

## 5. 根因分析

### 5.1 snapshot 失效（7 个失败）—— 环境链式断裂

```
.venv-kernel/bin/python  →  /tmp/dashr-py311/bin/python3.11   （悬空，目标已删）
        ↓ 测试 helper: existsSync(悬空 symlink)=false → 回退 'python3'
        ↓ 内核运行在 Python 3.14.4（系统解释器）
系统 python3.14 已装 ipykernel 7.3.0，但 ❌ 无 dill
        ↓ snapshot/restore 依赖 dill.dump/dill.load（src/python.ts:163,242）
        ↓ dump 失败 → manifest.json 从未写出 → 测试 ENOENT / assertion 失败
```

即：**文档承诺的「Python 3.11 内核（uv venv）+ dill」部署前提在本机已失效**，运行时静默回退到 3.14.4 且缺 dill，导致快照功能整体不可用。

### 5.2 docstring 失败（1 个）—— 疑似 Python 3.14 行为变化

`runtime.spec.ts`「keeps function docstrings intact」断言 `helper.__doc__` 精确等于 `'First summary line.\n    Details follow.'`，在 3.14 下不成立。与 5.1 同源（内核 Python 版本漂移），需在 3.11 下复验。

## 6. 问题清单（按严重度）

### 🔴 P0 — 快照功能整体失效
README「State Snapshot & Revival 💾 Full Namespace Snapshot (dill)」在当前环境不可用。需修复内核 Python 环境（重建 3.11 venv + `ipykernel dill`），或让运行时在缺 dill 时显式告警而非静默跳过。

### 🟠 P1 — docstring 回归
可能由 Python 3.14 引入；需在 3.11 内核下确认是否仍存在。

### 🟡 P2 — 文档/命名漂移（多处）
1. **`agent_message` vs `send_message`**：`CONTEXT.md` 术语表写 A2A 函数为 `agent_message(receiver, message, *, subagent_id)`，但 v0.1.8 实际桥接名为 **`send_message`**（`tool.send_message`）。实测 `tool.agent_message` → `unknown binding`。
2. **flat-global vs `tool.*`**：`CONTEXT.md`「Binding = flat global」及 `V0.1.5-development-plan.md`（Q8 平级 globals）描述的是旧形态；v0.1.8 已切换为统一 `tool.*` namespace，`rlm`/`agent_list` 等**不再是裸全局**（实测 `rlm(...)` 裸调用 → `NameError`）。
3. **`subagents-surface.ts` 头注释**仍描述「preset 的 entry-local `isolate: { replRuntime: true }` realm」旧架构；v0.1.8 已改为 HOST 平面全局挂载，注释过时。
4. **`@fgm-builds/dashr` vs `pgmi-builds`**：最近一次 commit（`ec7b844`）把 GitHub namespace 从 fgm-builds 改成 pgmi-builds，但 `package.json` 的 `name` 仍是 `@fgm-builds/dashr`，仅 `repository.url` 是 pgmi-builds，未同步。
5. **masking 数量**：ADR-0002 / V0.1.5 plan 写 7 个 masked 名，代码 `MASKED_TOOL_NAMES` 实际 **8 个**（多了 `report`）。

### 🟡 P3 — 观察项（供决策，非必然 bug）
1. **masking 对「直接 function-calling 面」无效**：ADR-0002 意图是「模型看不到这 7/8 个名」，但实测 masking 只作用于 REPL 内 `tool.*`；作为 dual-exposure（both 模式）副作用，`subagent`/`send_message`/`list_agents`/`interrupt_agent`/`workflow`/`ralph`/`subagent_fork` 仍出现在模型**直接可调用的工具面**。这是 both 模式与 masking 意图的结构性张力，需 maintainer 决策（是否要在直接面也收敛）。
2. **桥接工具错误风格不一致**：`rlm()` 参数校验失败返回**结构化 error 值**，`rlm_workflow()` 校验失败抛 **ToolCallError**，两种风格并存。
3. **README/描述措辞**：`package.json` description 写 `tool.*`，README 正文仍写 `tools.*`（复数，旧名），需统一。
4. **`compact` 依赖宿主压缩引擎**：本部署无 `ctx.compaction` 引擎，DASHR 的「Global Context Recency Window / compact」压缩能力未在此环境生效，需在目标部署形态下复验。

---

## 7. 建议

1. **优先修复内核环境**：重建 `.venv-kernel`（Python 3.11 + `ipykernel` + `dill`），消除悬空 symlink；否则快照功能与 7 个测试持续红灯。
2. **为缺 dill / 版本漂移加显式护栏**：运行时启动时探测 `dill` 与 Python 版本，缺依赖时降级快照并**告警到模型/日志**，而非静默跳过。
3. **同步文档与命名**：统一 `CONTEXT.md`（`agent_message`→`send_message`、flat-global→`tool.*`）、`subagents-surface.ts` 头注释、`package.json` `name`（fgm→pgmi）、README 的 `tools.*`→`tool.*`。
4. **明确 masking 边界**：在 dual-exposure 下重新定义「masking 语义」——是只收敛 REPL 内 `tool.*`，还是也要在直接工具面收敛，形成 ADR。
5. **CI 退出码**：核对 vitest 失败时是否向 CI 返回非零退出码，避免「红测试绿流水线」。
