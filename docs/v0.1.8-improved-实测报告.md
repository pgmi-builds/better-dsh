## 1. 本次变更（commit `7ec46ac`）

```
dashr: runtime-owned kernel environment + native delegation exposure
```

1. **内核环境自管**（新增 `src/kernel-env.ts`，210 行）：运行时自己 provision 一个托管 CPython 3.11 venv（`ipykernel` + `dill`），落在**包内 `.venv-kernel`**（不再 `/tmp` 悬空 symlink）。显式解释器被校验：缺 `dill` = 响亮告警（禁用快照），缺 `ipykernel` = 硬错误。
2. **原生 delegation 直接暴露**：masking 从 8 名收敛到**仅 2 名**（`send_message` + `report`）；`subagent`/`subagent_fork`/`list_agents`/`interrupt_agent`/`workflow`/`ralph` 直接暴露为 `tool.*` 成员；**`rlm`/`agent_list`/`rlm_workflow`/`rlm_ralph` 桥接全部删除**。
3. **Rebrand**：`@fgm-builds/dashr` → `@pgmi-builds/dashr`；RLM 术语在 CONTEXT/ADR 去强调。

## 4. 遗留问题（新发现）

### 🟡 4.1 包内 `dashr/README.md` 中后段仍描述旧架构

header 段已更新（`dsh-rlm-mode`→`dashr`、`RLMRuntime`→`ReplRuntime`、`ipython`→`eval`、kernel 自管），但**中后段未同步**，仍残留：

- 「**`ipython`** — the only tool the model may call directly」（应为 `eval`）
- 「FLAT top-level callables — `await name({...})`」（应为 `tool.*` member）
- 「bridge callables `rlm`, `send_message`, `agent_list`, `rlm_workflow`, `rlm_ralph`」（已删）
- 「Delegation and messaging (rlm, send_message, agent_list, rlm_workflow, rlm_ralph)」整段 `rlm()` API 文档（已删）
- install 段仍指 `dsh-rlm-mode` + `rlm-mode` preset（preset 已删）
- `dashr-kernel` group `isolate: { rlmRuntime: true }`（旧 realm 架构，现为 host-plane `dashr-repl`）

### 🟡 4.2 根 `README.md` 完全未 rebrand

根 `README.md` 仍是「# Dashr: RLM Plugin for `dsh`」+ `dsh-rlm-mode` npm badge + 完整 RLM 定位 + `rlm()` API 示例——本次 commit **未触碰根 README**。

### 🟡 4.3 `compact` 引擎本部署未挂载

`tool.compact` 返回 `{'context_tokens': 137635, 'error': 'compact() is unavailable: no ctx.compaction engine is mounted in this composition'}`——桥接存在，但本 composition 无宿主压缩引擎（与上版一致，非本 commit 引入）。

### ⚪ 4.4 观察项：会话续接时工具目录未随插件升级刷新

本会话（`session-5037d6a6`）跨过了插件更新 + 运行时重启，但**本会话的 system prompt（Tool Catalog）仍是旧版**——仍在声明 `rlm`/`agent_list`/`rlm_workflow`/`rlm_ralph` 可用，而实测运行时已 `unknown binding`。新开会话应得到正确目录，但「持久会话热升级插件后目录不刷新」值得留意。
