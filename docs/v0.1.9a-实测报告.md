## 本轮结构变化（对实测口径的影响）

1. **三桥成为真工具**：`agent` / `agent_message` / `agent_workflow` 现在是 registry 注册（与 `eval` 同宿主层）。模型**直调**（不经 cell）应当工作，且走完整 dispatch 管道（审计事件/presentation）。REPL 侧 `tool.agent(...)` 不变（auto-bridge 自动拾取）。手写 `AGENT_BRIDGE_SCHEMAS` 路径已删除——目录渲染单源。
2. **新增 `llm_completion`**：one-shot 无工具无历史 LLM 调用。参数 `{prompt, system?, maxTokens?}`，返回**纯文本**（string 根）或 `{error}`。路由 = 调用方 agent 的 provider/model。
3. **write 反馈环**：lsp server 在位的语言，write 结果带 `diagnostics` 摘要字段（计数+首条）；格式化在写前完成（单次写、单次审计）。无 server 语言零变化。

### §2 llm_completion
```
llm_completion({ "prompt": "Reply with exactly one word: PONG" })
```
- [x] 返回纯文本 `PONG`（string 根，非 {text} 包装）。
- [x] cell 内：`await tool.llm_completion({"prompt":"…"})` 返回裸 str `CELL-PONG`（auto-bridge 拾取，零 spawn——judge 场景成立）。
- [x] system 生效：强制尾缀 SYST-OK 的 system prompt 下，回复以 `SYST-OK` 结尾。
- [x] 参数校验为结构化 error：`maxTokens:0` 与 `maxTokens:5000`（>4096 上限）均返回 `{error:"…must be a positive safe integer no greater than 4096"}`，不抛。
- [~] 降级 finish → 结构化 error：**本路由不可触发**。`maxTokens:1` / `maxTokens:3` 实际返回了完整长输出（见缺陷 F8），说明 maxTokens 未端到端生效，"hits maxTokens → {error}" 场景在此 provider 上无法到达；abort 路径未做第一人称触发。
- [~] 无路由场景：结构化 error 为**源码级核验**（llm-completion.ts:93-96：无 provider/model 即 `{error:"requires a model route"}`），根会话第一人称不可达（exec.agent 恒在）。注意该行为与设计文档的 default-model 回落说法不一致，见缺陷 F5。
