## 本轮结构变化（对实测口径的影响）

1. **三桥成为真工具**：`agent` / `agent_message` / `agent_workflow` 现在是 registry 注册（与 `eval` 同宿主层）。模型**直调**（不经 cell）应当工作，且走完整 dispatch 管道（审计事件/presentation）。REPL 侧 `tool.agent(...)` 不变（auto-bridge 自动拾取）。手写 `AGENT_BRIDGE_SCHEMAS` 路径已删除——目录渲染单源。
2. **新增 `llm_completion`**：one-shot 无工具无历史 LLM 调用。参数 `{prompt, system?, maxTokens?}`，返回**纯文本**（string 根）或 `{error}`。路由 = 调用方 agent 的 provider/model。
3. **write 反馈环**：lsp server 在位的语言，write 结果带 `diagnostics` 摘要字段（计数+首条）；格式化在写前完成（单次写、单次审计）。无 server 语言零变化。

```

```
- [ ] 返回纯文本 `PONG`（string 根，非 {text} 包装）

- [ ] 无路由场景（若有）：结构化 error

### §3 write 反馈环
- [ ] 写一个带类型错误的 .ts 文件 → write 结果含 `diagnostics` 字段（"1 error(s) — first: TS…"）

- [ ] 写 .txt（无 server）→ 结果与旧版完全一致（无新字段）
- [ ] 格式化：写风格混乱的 .ts（如 `let  x=1`）→ 盘上内容已格式化（`const x = 1;` 或该 server 的风格）
