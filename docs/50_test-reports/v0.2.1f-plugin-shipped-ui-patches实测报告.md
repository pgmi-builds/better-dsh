## 2. 实现面（代码清单）

- `dashr/cordis.patch.yml`：+`connection` 行覆盖（整行重述 + `trustedHosts: !!js (env).split(/\s+/).filter(Boolean).concat(ctx.webRuntime.trustedHosts)`；⚠ `!!js` 是 scalar tag，表达式不能以 `[` 开头——flow-seq 会被 yaml 拒）。
- `dashr/src/web-trust.ts`（新，host 半）：`buildBootScript` 纯函数 + `installWebTrust`（`webserver/index-inject` 监听，emit 时新鲜读 config）。一个内联 head script 双效：trusted hostname → `window.__DSH_TRANSPORT__={ownsHost:true}`（无 fetch/openStream，唯一效应 = isLoopback 翻真；不覆盖已有 transport）；mobile 阈值 → `window.__DASHR_MOBILE__`。
- `dashr/src/mobile/gesture.ts`（新，纯）：`isRecognizedSwipe`（起点∧距离∧速率 + 横向占优 + touch/pen only）、`isInteractiveOrigin`、`isNarrowViewport`、`resolveMobileConfig`。
- `dashr/src/mobile/client/index.ts`（新，client 半）：`setupMobileLayout`——`<style data-plugin data-plugin-css>` 注入（媒体查询 + `[data-sidebar-collapsed]` + `!important` 覆盖内联 grid template → 侧栏轨 0）+ document 级 pointer 监听 → `ctx.layout.toggleSidebar()`（窄视口=翻 narrowExpanded）。
- `dashr/src/index.ts`：Config + `trustedPageAuthorities` / `mobile`（schema 默认 enabled）；apply 挂 `installWebTrust`。
- `dashr/src/failover/client/index.ts`：client 入口挂 `setupMobileLayout`；package.json `dsh.client.inject` + `@deepseek-ai/dsh-client-ui-layout`（模块表边）。
- tsconfig exclude + `src/mobile/client`（沿 failover/client 的 client 半约定）。

## 3. 病因与定性回执（P2 复诊闭环）

- prod 消息 `…failed: settings are unavailable in this browser` = 浏览器侧 `isLoopback` 门（`ui-settings` memory 持久化终态不可用），非服务端 fence。
- 上游定性（设计笔记实证）：有意 = "非 loopback 关 Host 持久化（偏好进程本地、页面照常）"；无人设计 = mirror 把 memory 做成终态不可用 + trustedHosts 未传导到 host facts——当年源码 patch 存在的全部理由。
- B 机制恢复的正是设计意图形态（remote 页面照常 + Host 持久化）。

## 7. Round 2（2026-09-03 user 实测反馈闭环）

- **阈值**：速率默认 0.35 → **0.2 px/ms**（"要求太快"裁定）。

- **新增右栏手势**：右缘带左滑 `openDetails`、非左缘右滑 `closeDetails`（面板状态读 AppFrame 语义属性）。

- **Models 页复诊**：三条 RPC（llm/listProviders、llm/listConfigurableProviders、settings/describe）loopback 直连全 ok——4999 后端无恙；user 手机所见的 Models 失败实为 prod（v0.2.1f 未部署）。

## 8. Round 3（2026-09-03 前端机制实证 + sidecarx 对齐）

- **机制链真浏览器实证**（CDP 驱动 google-chrome headless，经手机同款拼写 `192.168.31.130:4990`）：`window.__DSH_TRANSPORT__ = {"ownsHost":true}` 翻真；Settings > Models 页渲染出目录（"Enter your API keys… DeepSeek / Edit / Add a custom provider"）；截图 `.scratch/models-page-proof.png`。脚本位次（HTML 实测）：queue script(100) → … → `__DSH_BOOT__`(3637) → **boot script(23778)** → shell 主入口(25168)——先于一切 application bundle 物化。
- **sidecarx 对齐**（user 参照 `sidecarx/src/webclient/src`）：参照实现**无速率门槛**（`app.js:332` `SWIPE_THRESHOLD=50` + 左缘带 40px + 展开态任意起点左滑关 + `absDY>absDX` 拒绝；overlay-viewer 同款数学）——默认改为 sidecarx 同款：distance 50 / edgeBand 40 / **velocity 0（禁用）**；三条件模式保留为配置旋钮（armed 时生效，慢速拖选 ~0.13 px/ms 为标定参考）。429/429 绿。

## Round 4（2026-09-03）— 手势整体重写：z_dsh-alpha `1706b81` 逐条照搬 + 速率门

## 附：hashline edit 升级透传 bug（2026-09-03，commit `e27fdec`）

**症状**（user 报告）：4999 会话内 agent 带齐 `sandbox_permissions:"danger-full-access"` + `justification` 重试 edit，审批卡永不弹，循环收 `[sandbox: file access denied under workspace-write mode]` + escalation-available 提示。

**证据**（session `8e966430`，zstd session log）：8 次升级 edit 全部 plain 拒绝，全程 `approval/asked` 事件数 = 0；同 session 的 `write` 升级正常弹卡并被 `allowed-once`。上游 `approveEscalation` 是 fail-closed 设计——升级参数若真触达，要么弹卡要么抛专用错误文本，绝不会返回 plain 拒绝+提示。

**根因**：better-dsh vendored hashline `tool-edit.js` 在 `sandbox.resolvePolicy("edit", {path, edits}, exec)` 调用点手工重构对象，丢弃了 `sandbox_permissions`/`justification`（讽刺的是 `canonical` 里就带着——`contract.normalizeRequest` 显式回填）。`resolvePolicy` 见不到字段 → 永远返回 standing policy → 围栏拒绝。`batch_edit`/`undo_last_edit` 传 `canonical`，无此问题；`write`/`bash` 走上游 tool-fs/tool-bash 传全参，无此问题。

**修复**：调用点透传两字段；回归测试 `test/url-schema/escalation-forward.spec.ts`（stub sandbox 捕获 resolvePolicy 入参 + 预中止 signal 隔离 fs 半边）2 例；427/427 + tsc 0；已部署 4999。**注意 prod（3080，npm 0.2.1-d）同样带此 bug**，随下个发布版本收敛。
