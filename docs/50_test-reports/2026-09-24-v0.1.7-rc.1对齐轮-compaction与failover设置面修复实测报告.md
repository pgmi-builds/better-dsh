# v0.1.7-rc.1 对齐轮 — compaction / failover 设置面修复实测报告（2026-09-24）

分支 `align/v0.1.7-rc.1`（基线 main = 0.2.4-b，prod 同版）；提交 `5aa9ca0` + `eea888f`。

## 一、症状与根因

prod（3080）已运行 dsh **0.1.7-rc.1**（npm，`~/.local`）+ better-dsh **0.2.4-b**。用户报告：

1. **compaction 组件不在 Settings/General 出现**；
2. **failover 设置行在，但选择后报"cannot save to file"**。

根因只有一个 —— **dsh 0.1.7 移除了 settings.yaml namespace 模型**：

| 0.1.6 及以前（better-dsh 0.2.4 所说方言） | 0.1.7-rc.1（现实） |
|---|---|
| `SettingsProvider.installSection(ctx, ns, schema, base, hooks)` | **已删除**（新 `SettingsForms` 无此方法） |
| namespace = 自由字符串，存 `settings.yaml` | namespace = **Loader entry id**；值以 profile patch 用户层落盘（configEditor） |
| `settings.get(ns)` | 已删除 |
| 自定义写校验钩子（validate） | 无此 seam（只剩 schema 校验） |
| v3 消息 source `{kind:'plugin', plugin}` | v4 producer-owned kind（`plugin:better-dsh`，migration fallback 即此形） |

两个症状的精确链条：

- **compaction 行消失**：`CompactionRow.loadConfig()` 在 `describe()` 里找不到 `ns === 'compaction-tuning'`（0.1.7 的 ns 是 entry id `dashr-compaction-tuning`）→ 返回 null → `CompactionRow` 对 absent namespace **渲染 null**。行没注册失败，是自己选择不渲染。
- **failover 存不进**：行本身渲染不依赖 namespace（空默认也渲染），但 save 走 `remote.settings.update('failover', …)` → 0.1.7 `SettingsForms.write()` 抛 **`No configurable plugin entry "failover"`** → 行内 toast `Save failed: settings/rejected: …`（用户转述为"cannot save to file"；该字符串不属上游也不属 better-dsh，是 toast 模板 + 服务错误的拼接）。
- **隐藏第三伤（用户未及看到）**：两个 host 半的 `ctx.inject(['settings'], sctx => sctx.settings.installSection(…))` 在 0.1.7 会 TypeError —— failover 的 per-turn 切换链、compaction 的引擎同步实际都已残废。

## 二、修复（对齐 upstream `agent-default-model` 范式）

`packages/core/agent-default-model/src/index.ts` 是 0.1.7 的官方样例：`.volatile()` 字段以 `Volatile<T>` live ref 进入 resolved config（runtime 原地改写 ref，读侧 `.get()` 即实时）、`settings.configure({auto:false}, fiber)` 压掉原生自动表单、持久化交给可选 `configEditor.edit(entry,…)`。better-dsh 逐条对齐：

- **schema**：`fallback1/2`、`thresholdRatio` 加 `.volatile()`（`retainTokens` 保持非 volatile = 组合面专用，表单写永不触碰）。
- **failover host**：删 installSection；`source` 每次请求/失败实时 `readSlot(ref)`；`configure({auto:false})`。
- **compaction host**：给引擎一个 **frozen getters 视图**（`thresholdRatio`/`retainTokens` 为 getter，读 `live()`），引擎每次 `resolveTargetPolicy()` 自然读到新值 —— 无需 re-apply、无需事件；保留 `retainRatio` 删除语义；advisory 窗口探测保留并降级为告警日志（0.1.7 无写校验 seam）。
- **client**：ns 常量改为 entry id（`FAILOVER_SETTINGS_ENTRY='dashr-failover'`、`COMPACTION_SETTINGS_ENTRY='dashr-compaction-tuning'`）；UI locale/slot id 不变。
- **其它 0.1.7 破面清扫**：`agent/session-start` → **`agent/created`**（serial，dispatcher 注入 agent）；ContentBlock **`'tool-result'` 移除** → role-`'tool'` 消息 + `message.isError`；session v4 source kind 在 `MessageSourceMap` 里声明 **`'plugin:better-dsh'`**；`SubagentResult.output` readonly 化。

## 三、验证（验收 = 改动同类：真实运行时里设置面可用）

环境：Dev/Test 1，upstream checkout 切 **dsh-v0.1.7-rc.1**，全量 `pnpm run build`，内嵌副本 = 本修复；`PORT=4988`（4999 被 superd PoC 占用）。

1. **构建卫生**：`tsc --noEmit` **0 错**；vitest **600 passed / 1 skipped / 0 failed**（54 文件）。
2. **第一人称 CDP 实测**（`.scratch/probe-049/verify-settings-049.mjs`，真实浏览器走 token URL → Settings → General）：
   - `Auto-compact threshold` 行 **可见**，stepper 在位，点击后 **无 "Save failed"**；
   - failover 两个 select 目录填充（deepseek-official/*），选择 `deepseek-official/deepseek-flash` → **saveError: false**、**valueRetained: true**；
   - `pageErrors: []`；截图 `.scratch/probe-049/settings-general.png`。
3. **落盘证据**：`.dsh-test/profiles/web/cordis.patch.yml` 出现
   `dashr-compaction-tuning.config.thresholdRatio: 0.75`（≠ 默认 0.8 = UI 写入）与
   `dashr-failover.config.fallback1: deepseek-official/deepseek-flash`（= 探针所选）—— 0.1.7 的 entry-patch 持久化闭环成立。
4. **回归探针**：boot graph 含 `better-dsh` + client.js URL；`/plugins/??better-dsh/client.js&rev=…` 200，与 `lib/client/index.js` 字节一致（服务端仅追加 sourceMappingURL）。

## 四、本轮环境新账（全部已处理，后来者必读）

1. **根 package.json 新 patch：`vite: ^6.0.0`** —— rc.1 起 `apps/desktop/tsdown.config.ts` 运行时 `import { build } from 'vite'`；本机 Node 走 unrun 加载 config，从 `.unrun` 缓存目录解析不到根 vite → build:lib 死。（上游 CI native loader 无此问题。）
2. **孤儿残骸**：rc.1 删除了 `packages/settings/settings-file`，但 checkout -f 不清 gitignored `lib/` → tsdown workspace glob 吞进旧 `lib/types`（引用已不存在的 `SettingsProvider` 导出）→ build:lib 硬错。已 `rm -rf packages/settings/settings-file`。
3. **cordis 身份**：副本 devDep `cordis: 4.0.2`（registry）与工作区全量的 **vendor/cordis 4.0.4** 是两个声明实例 → 增补（settings/tools/Events）分裂 → 212 个假错。副本改 `workspace:*` 后归一 → 0 错。sync 脚本已把 vendor 家族纳入手术名单。
4. **同步脚本**：`.scratch/sync-better-dsh-copy.sh`（rsync → 手术 → install → tsdown → build-client → tsc）。手术名单 = `/tmp/workspace-provides.txt` ∪ `/tmp/vendor-provides.txt`（后者由 `vendor/*/package.json` 生成，易失，脚本失效时先重建）。
5. **`installSection` grep 教训**：`git grep … | head` 截断曾让 0.1.6 树看起来"没有 installSection"——head 截断会伪造结论，长输出一律落文件再查。
