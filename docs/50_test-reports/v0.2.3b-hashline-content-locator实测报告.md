## 4. 实测发现：宿主 fs 观察策略是跨会话 edit 的另一道（设计内）闸

S2 盲 edit 返回 `[E_NOT_OBSERVED] The file has not been observed in this session
(read-before-write policy). Call read() first` ——这是 **`dsh-fs-observation-policy` 宿主插件**
的 observed-state 守卫（owner=agent 会话的 WeakMap，read/write/edit 记版本），**不是** hashline
served 账本。定性：

- **保留**（user 裁决语义："安全守卫在确认覆盖/见过"——read-before-edit 正是宿主层的"见过"）；
  本 change 的范围是把 hashline 层的**重复**session 账本拿掉，不是拆宿主守卫。
- 事故剧本（S1 write → fork 子会话 edit）在原线上之所以先报 hashline 错，是 fork 继承了观察态；
  hashline 层修复后，**同进程 fork 续聊**的 edit 将直接由内容快道放行（fork 不再需要冗余 read）。
- 全新无关会话（如本 S2）盲 edit 被宿主拦——符合"读过才许改"的常理，非回归。
