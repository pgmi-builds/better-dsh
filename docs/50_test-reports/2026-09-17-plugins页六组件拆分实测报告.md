## 一、机制事实（对 prod 0.1.3 线 plugin-manager 源码核实）

- 插件页卡片描述 = 包 manifest `description` 字段（`BundleInfo.description` JSDoc："`description` of the package manifest"）。better-dsh 此前缺该字段 → 卡片无描述。官方包走 locale 表（`builtinAgentTeamTitle/Description`），非官方回退 manifest。
- 页面"组件" = bundle patch 的 **insert 行**（`declaredRows()`：inserts 才进 `rows`；非 insert 行进 `overrides`，该页不显示）。行开关 = 向 profile 用户层 patch 写 `{id, disabled}`，HMR 即时生效（`writePluginEnabled(profile.patchPath, …)` + `reload()`）。
- 0.1.5-rc.2 测试线无 plugin-manager（无行开关 UI，仅只读 inventory）；行结构为两线共用的 host 侧事实。

## 二、交付物

1. `package.json`：`description` 逐字取 awesome-dsh-plugins listing en 文案（与市场单源一致）；新增 5 个子路径导出（`./url-schemes`、`./failover`、`./compaction-tuning`、`./web-trust`、`./mobile`）。
2. `cordis.patch.yml`：6 条 insert（dashr-repl 核心 / dashr-url-schemes / dashr-failover / dashr-compaction-tuning / dashr-web-trust / dashr-mobile）；compaction 再启用三条与 `connection` fence 保持 override 行（原生页不列 override——做成 insert 需 fork 上游模块，不采纳）。
3. 配置键迁移：`urlSchemes`/`hashline`/`trustedPageAuthorities`/`mobile` 离开 dashr-repl Config，落所属行 schema（`DSH_TRUSTED_HOSTS` 派生默认保留在 web-trust 行 schema；MOBILE_CONFIG 原文迁至 mobile 行）。
4. **顺序不变式结构化**：`native-capture` 升为共享模块（tsdown 多入口 chunk 共享 `native-capture-x_Hos2e8.js`，单例 WeakMap）；wire mask 监听器第一步 `captureAllTools(agent)` 后才 restrict——两行激活顺序无关（`lib/index.js` 与 `lib/url-schemes/index.js` 实测引用同一 chunk）。
