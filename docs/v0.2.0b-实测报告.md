## §3 hashline-edit（v0.2.0b 主体）

- [x] **read 锚面不回归**：全程 `HASH│content` 行锚（本报告所有探针读写均经此面）。
- [x] **edit 锚元组落盘**：`{path, edits:[[hash,hash,text]]}` 一击替换成功，响应为 hashline diffstat 形态（`Successfully edited 1 file(s) — 1 of 1 edit(s) applied. Added 1 line(s), removed 1 line(s).`），未触碰行锚点稳定不变（s33/AuN/nyO/DBc 跨编辑保持）。
- [x] **drift 校验**：复用已失效锚（`zlr`）→ `[E_BATCH_ABORT]` + `[E_STALE_ANCHOR] "zlr"` 硬拒，**整批原子、零写入**。
- [x] **undo_last_edit 回退**：`Removed 1 line(s) … restored 1 line(s)`，diff 展示回退；被恢复行的锚 hash 与原锚完全一致（**hash 确定性**：同内容同锚，双向稳定）。
- [x] **edit 引入类型错误 → 结果文本附诊断摘要**（spec 关键场景）：main.rs 好态下锚编辑 `let x: u32 = "edit-introduced"` → edit 结果第二行即 `1 error(s), 1 hint(s) — first: mismatched types…`。post-execute 钩子端到端成立；edit 无 format（D3 取舍符合）。
- [x] **shadow 生效（行为证）**：edit 呈 hashline 语义（锚元组/E_STALE_ANCHOR/diffstat/undo 配对）——与宿主原生 old_string/new_string 形态完全不同；mask 名单无 `edit`（九名不变）；绑定集 edit/undo_last_edit 在位。**guidance sections 在场**：本会话 system prompt 携带 hashline 编辑指引全文（bare 3-char HASH anchor 用法、undo_last_edit 说明、`HASH│content` 行格式、`[E_RANGE_STALE]`/`[E_RANGE_UNSERVED]` 词汇表）——compiled defaults 对内建 tool guidance 的同层 shadow 第一人称可见。
- [x] **write preview + 诊断 + 格式化三附加共存**：一笔 create 写入混乱风格坏内容（`src/bin/messy.rs`，真 cargo target）→ 单一结果同时含 ① `Created <path>` ② 诊断行（针对**落盘后**内容）③ Auto-read preview 展示 **rustfmt 归整版**（盘上字节核验一致：`pub fn messy_v020b(x: i32) -> i32 {` 多行展开）。F11（create 路径格式化）与 preview/诊断叠加态不互斥。
